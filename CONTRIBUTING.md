# Contributing to The Guardian OS // Operative Guidelines

We welcome high-performance contributions to the Guardian OS. To maintain the platform's "Museum-Tier" quality and technical authority, all contributors must adhere to the following protocols.

## 1. Quality Standards
- **Aesthetics**: Every UI change must adhere to the **Absolute Premium UX** guidelines (Glassmorphism, Shimmer Animations, High-Authority Typography).
- **Integrity**: All code must be type-safe and pass a full production build (`npm run build`) before submission.
- **Privacy**: No contribution shall compromise the "Zero-Retention" data protocol.

## 2. Development Protocol
1.  **Fork the Command Center**: Create a personal fork of the repository.
2.  **Initialize Feature Branch**: Use descriptive branch names (e.g., `feat/neural-delta-v2`).
3.  **Execute & Verify**: Ensure all changes are verified in a local environment.
4.  **Submit Intel**: Open a Pull Request with a detailed summary of the "Tactical Upgrade."

## 3. Pull Request Review
Every PR will be audited by the core Guardian team for:
- Mathematical accuracy of AI formulas.
- Geospatial intelligence consistency.
- Performance and visual fidelity.
